# RecoveryOS Production Failure Matrix

This matrix specifies the automated behavior, recovery protocols, and operator escalation paths for all failure modes across the RecoveryOS production ecosystem.

---

## Failure Matrix Reference Table

| # | Failure Mode | Automated Detection | Expected System Behavior | Retry Semantics | State Transition | Operator Action | Recovery Action | Escalation Condition |
|:---|:---|:---|:---|:---|:---|:---|:---|:---|
| **1** | **API Service Unavailable / 503** | Cloud Run HTTP 5xx errors; `/api/health` probe failure | Cloud Run automatically restarts failed container instances; upstream clients receive 503 with retry-after | Upstream client exponential backoff (1s–30s) | No state created or mutated in Firestore | Check Cloud Run logs for container crashes or memory exhaustion | If service fails to recover, roll back to rollback reserve `recoveryos-00006-jwt` | Outage $> 2$ minutes or restart crash-looping |
| **2** | **Pub/Sub Publishing Failure** | `PublishError` logged; `recoveryos_publish_failures_total` counter increments | API returns HTTP 500 `Failed to dispatch workflow asynchronously`; workflow record marked with failure metadata | Immediate client retry or operator manual redrive | Workflow remains in `CREATED` state; version remains `1` | Inspect GCP Pub/Sub IAM permissions for service account `recoveryos-runtime` | Re-dispatch scenario or trigger operator recovery endpoint | Publish failure rate $> 1\%$ over 5 minutes |
| **3** | **Worker Ingestion Crash (Before Claim)** | Push delivery HTTP 500 / TCP connection timeout | Pub/Sub receives NACK/timeout; message retained in subscription backlog | Pub/Sub exponential retry up to 5 attempts | Workflow remains in `CREATED` state; no lease written | Inspect `recoveryos-worker` logs for OOM or startup exception | Worker restarts automatically on next push attempt | Unacknowledged messages $> 50$ or backlog age $> 60\text{s}$ |
| **4** | **Worker Crash (After Claim, Before State Mutation)** | Worker dies while holding `OperationClaim`; message unacknowledged | Lease remains in `PENDING` state until `expires_at` (60s); Pub/Sub retries push delivery | Re-delivered message checks lease expiry; succeeding worker reclaims lease | State remains `CREATED` until re-delivered worker advances it to `EXECUTING` | Monitor diagnostics endpoint `GET /api/workflows/{id}/diagnostics` | Auto-recovers after lease expiry (60s) upon next Pub/Sub retry attempt | Worker crash loops continuously across multiple instances |
| **5** | **Worker Crash (After Mutation, Before ACK)** | State updated to `EXECUTING` in Firestore, but worker process crashes before HTTP 200 returned to Pub/Sub | Pub/Sub retries message push to worker; re-delivered message checks `OperationClaim` | Re-delivered message encounters `status == COMPLETED` in `OperationClaim` | Workflow remains in `EXECUTING` (no duplicate mutation); re-delivered message returns ACK (200) | None required (idempotent deduplication handles cleanly) | Automated deduplication returns HTTP 200 and ACKs message | If duplicate messages persist beyond 5 retries |
| **6** | **Duplicate Pub/Sub Message Delivery** | `recoveryos_duplicate_claims_total` counter increments; `EVENT_WORKFLOW_DUPLICATE` logged | Worker detects existing `OperationClaim` with status `COMPLETED` or active lease | Replay is safely ignored; returns `SKIPPED_DUPLICATE` and ACKs message | No duplicate state mutation; version remains unchanged | None required; monitor metric `recoveryos_duplicate_claims_total` | N/A (Handled deterministically by `WorkflowEventConsumer`) | Duplicate rate $> 20\%$ of total throughput |
| **7** | **OCC Version Conflict (Stale Event)** | `StaleWorkflowStateError` raised; `recoveryos_occ_mismatches_total` counter increments | Worker detects `expected_version != workflow.version`; returns HTTP 500 NACK for retry | Pub/Sub backs off and retries delivery | Workflow remains in current valid state; no rollback or corruption | Inspect timeline events to determine if an out-of-order event arrived | Allow Pub/Sub retry to fetch fresh workflow state and version | OCC conflict count $> 5$ for a single workflow |
| **8** | **Malformed Message / Poison Pill** | `MessageValidationError` raised; `WORKER_INVALID_MESSAGE_SCHEMA` logged | Worker immediately routes message to dead-letter decision; returns HTTP 200 to Pub/Sub to prevent infinite retry loops | Not retried in worker; forwarded to DLQ if delivery attempts exceed 5 | No workflow mutation performed | Inspect DLQ subscription `recoveryos-workflow-execution-dlq-sub` | Review malformed schema and fix producer contract | DLQ accumulation $> 5$ messages in 15 minutes |
| **9** | **Non-Existent Workflow Event** | `ConsumerExecutionError` raised; `EVENT_WORKFLOW_NOT_FOUND` logged | Worker detects missing Firestore workflow document; returns permanent fatal decision (ACK/DLQ) | No retry in worker | N/A (document does not exist) | Check API dispatch logs for orphaned message IDs | Trace producer origin or purge phantom message | Repeated orphaned messages from untrusted source |
| **10** | **Cross-Tenant Access Attempt** | `EVENT_TENANT_MISMATCH` logged; HTTP 403 returned | Request rejected immediately at API / Consumer boundary; audit log emitted | Rejected (403 Forbidden); no retry | No tenant data accessed or mutated | Review security audit logs for unauthorized tenant token usage | Revoke compromised JWT or update tenant access configuration | Repeated cross-tenant access attempts from single IP/token |
| **11** | **Transient Firestore Failure** | `GoogleAPICallError` or gRPC `UNAVAILABLE` exception caught | Worker catches transient exception; logs `WORKER_TRANSIENT_ERROR` and returns NACK | Pub/Sub retry with exponential backoff | Firestore transaction aborts; state unchanged | Check Google Cloud Firestore status dashboard | Automatic recovery once Firestore connectivity is restored | Firestore outage $> 3$ minutes |
| **12** | **Stuck Workflow ($>300\text{s}$ Inactive)** | Diagnostics endpoint reports `is_stuck: true`; `stuck_reason` populated | Workflow identified as inactive in non-terminal state without active worker claim | Automated worker retry or manual operator recovery trigger | Workflow advances from `EXECUTING` upon operator recovery redrive | Call `GET /api/workflows/{id}/diagnostics`, then `POST /api/workflows/{id}/recover` | Redrive via operator recovery API endpoint with fresh idempotency key | Stuck workflows $> 10$ across all tenants |
| **13** | **Terminal Workflow Re-execution Attempt** | `EVENT_WORKFLOW_TERMINAL_SKIP` logged | Worker detects `COMPLETED` or `ESCALATED` state; returns `SKIPPED_TERMINAL` and ACKs | Message dropped safely without processing | State remains in terminal state; version unchanged | None required | N/A (Terminal states are strictly immutable) | Repeated attempts to re-execute closed workflows |
| **14** | **Unauthenticated Worker Access Attempt** | Cloud Run Google IAM Edge returns `HTTP 403 Forbidden` | Request blocked before reaching worker application layer | Request dropped | No internal worker code executed | Inspect GCP Cloud Logging for unauthorized ingress attempts | Ensure all internal callers use valid Google Cloud OIDC tokens | High rate of unauthorized ingress attempts at private edge |
| **15** | **Dead Letter Queue (DLQ) Accumulation** | Messages present in `recoveryos-workflow-execution-dlq-sub` | Messages exceeding 5 delivery attempts routed to DLQ topic | No automated retry from DLQ | Original workflow preserved in last known valid state | Pull messages from DLQ subscription using operational runbook | Inspect poison pill payload, fix root cause, and redrive if appropriate | Any unexamined message in DLQ subscription |
